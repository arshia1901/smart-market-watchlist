Architecture

How the Smart Watchlist is wired, how data moves through it, and what it would take to serve 200,000 concurrent users across 20,000 stocks on Google Cloud. Every number below is measured on this running system or derived from it — nothing is estimated for effect.

1. High-level architecture

Six containers, one command. The thesis is simple: the server never does per-user arithmetic. Everything expensive is asynchronous and shared; the personal work — the ranking — happens in the browser.

Three tiers, and what each one costs

That split is enforced by the API shape rather than by discipline: /api/quotes carries no per-user data whatsoever, so it can be cached once and served to arbitrarily many viewers. The personal payload is fetched once per session, because baselines freeze at sign-in.

2.1 Ingestion tick

One loop, one cadence — 60 seconds, the real grid. It re-reads the tracked set every tick, so a stock added from the search box starts being collected on the very next cycle, and a stock removed from the last list holding it stops.

Why the event time and not the price. Feeds retry and deliver out of order. A delayed packet with an older price arriving after a newer one would rewind the price and invert every move. Comparing on the quote's own timestamp — never arrival time — is the one rule that makes last-known-value robust rather than sloppy. A new stamp with the same price is applied: a genuine minute in which the stock didn't move.

2.2 Statistics engine

Its own container, no dependency on the API. It tails the stream and maintains one σ per stock over a fixed 750-bucket window — two trading sessions of one-minute returns, the same window for every stock.

Why winsorise against MAD and not against σ. Clipping outliers against σ is circular — the outlier is already inside the estimate you would clip with. The median absolute deviation is not moved by one bad tick. Observed live on the canary: a −20% then +50% jump between consecutive buckets moved σ from 0.0709% to 0.0776%. Unwinsorised it would have inflated roughly 25× and flattened every other stock's signal for two days.

2.3 Sessions and the shift register

"Since you last checked" is measured from the start of your previous session. Sign in is the only event that moves that anchor; refresh reads; sign out closes. A sign-in while one is open is refused (409) rather than silently re-anchoring.

N is one number per session — trading minutes between the previous session's start and now, counted on the NSE calendar (closed hours add nothing). Because √N is a common factor across every row, N cannot change the ranking; it only scales the band labels. That is why an approximate calendar is safe for ordering and only freshness needs the calendar to be exact.

2.5 Warm-up on add — no two-day cold start

σ needs 750 one-minute samples. A stock nobody was collecting has none. Rather than wait two sessions, the system pulls that stock's real 1-minute bars for today, measures its real σ, and back-fills the window by resampling those real returns — anchored to end exactly at the live price. Rankable within one minute, with its own volatility, flagged provisional σ until genuine history replaces the fill.

Two ways to read "200,000 concurrent"

As 200,000 open pages polling. The shared payload is identical for everyone, so the edge answers it and the origin sees a trickle. The only per-user request is one /api/watchlist per session. This is the cheapest correct architecture and it is what the prototype already does; the CDN simply replaces nginx's 2-second cache.

As 200,000 open sockets. If sub-second push is required, replace polling with a fan-out tier: WebSocket servers on GKE (or Cloud Run with session affinity) that subscribe to the shared quote frame once and broadcast it — 200,000 connections × one small frame per minute is a few GB of connection state across a handful of nodes. Nothing upstream changes; the shared/personal split is what makes the broadcast a single message.

What does not change

  • The formula and where it runs — |r| / (σ·√N) in the browser. Serving cost per user stays near zero.
  • Write-if-newer on event time, per shard. Sharding by symbol keeps each symbol's ordering local.
  • The two-payload API shape. It is the reason the CDN can do the heavy lifting at all.
  • σ's window and its event-driven cadence — 750 one-minute samples, recomputed only when a bucket arrives.
The honest constraints. A free per-symbol HTTP feed cannot serve 20,000 symbols a minute; this needs a licensed vendor feed. No free source for Indian equities is licence-clean, and a product at this scale must have a data contract. The login write amplification is real and is the first thing to re-architect past a single Postgres primary. Everything else on this page is a hosting decision, not a redesign — the seams are already process boundaries in the prototype.
